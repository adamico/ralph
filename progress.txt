04-tests: Added tests/pick_next_issue_spec.sh — plain bash, no bats. Sources bin/ralph (which short-circuits when sourced) to exercise pick_next_issue() across 9 fixture scenarios: lone ready, lowest-filename tiebreak, done-skipping, undone vs done Blocked-by deps, multi-dep with one undone, all-blocked → ALL_BLOCKED=1, all-done → empty pick, and 'blocked' status skipped. Captures stdout via tempfile so the function's side-effect ALL_BLOCKED survives (command substitution would fork a subshell). 14/14 assertions pass.
05-github-backend: Added GitHub Issues backend to bin/ralph. New config knobs BACKEND (fs|github, default fs), GH_MILESTONE, GH_REPO, GH_LABEL_READY (status:ready), GH_LABEL_BLOCKED (status:blocked). pick_next_issue_gh() lists open issues in milestone via `gh issue list --json number,labels,body`, filters by ready label, sorts by issue number, parses each body for `Blocked-by: #NN, #MM` and treats a dep as done iff `gh issue view` reports state=CLOSED; sets ALL_BLOCKED=1 when readies exist but every one has an undone dep. build_prompt_gh() instructs the agent to gh-view the issue, run tests/lint, then either close + commit progress on success or stash + add blocked label + comment Blocked-reason on failure. iterate_once now dispatches on $BACKEND: github path emits COMPLETE when no open issues remain in milestone and BLOCKED when ALL_BLOCKED=1, with rc 20/21 unchanged so `ralph run N` halts correctly. Sanity: existing fs-backend tests still 14/14 pass; bash -n clean.
